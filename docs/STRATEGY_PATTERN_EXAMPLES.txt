╚════════════════════════════════════════════════════════════════════════════╝

1. Single Responsibility Principle (SRP)
   ✓ Match class: holds state (score, squads)
   ✓ Strategy: defines behavior (how to simulate)
   ✓ Factory: creates objects
   ✓ Each class has ONE reason to change

2. Open/Closed Principle (OCP)
   ✓ Open for extension: Add new strategies easily
   ✓ Closed for modification: Don't change Match class

3. Liskov Substitution Principle (LSP)
   ✓ All strategies are interchangeable
   ✓ You can pass any strategy to Match

4. Interface Segregation Principle (ISP)
   ✓ MatchSimulationStrategy interface is minimal
   ✓ Only simulate() and get_name() needed

5. Dependency Inversion Principle (DIP)
   ✓ Match depends on MatchSimulationStrategy (abstraction)
   ✓ Not on concrete RandomMatchStrategy (implementation)

All 5 SOLID principles in play!
